# История версий

Каждая сборка получает свой номер. Файл архива называется `Olan vN.zip`,
внутри папка всегда `olan` — чтобы путь на компьютере не менялся.

---

## v46 — текущая

**Сайт открывается даже на очень медленном интернете.** Проверено на
эмуляции 2G (50 КБ/с, задержка 0,4 с):

- заставка с логотипом появляется через 2,7 с;
- сайт готов через ~10 с;
- всего скачивается ~400 КБ, включая фото баннера.

Раньше одни только скрипты, стили и тексты весили ~2,4 МБ и шли без сжатия.
На такой связи это больше минуты.

- **Сжатие на сервере.** Скрипты, стили, HTML, JSON и SVG уходят в brotli,
  старым браузерам — в gzip.

  | Файл | Было | Стало |
  |---|---|---|
  | Основной скрипт | 640 КБ | 138 КБ |
  | Стили | 126 КБ | 19 КБ |
  | React | 143 КБ | 40 КБ |

  `npm run build` заранее кладёт рядом готовые `.br` и `.gz` (скрипт
  `scripts/precompress.mjs`). Если их нет, сервер сжимает сам и запоминает
  результат.
- **Ответ «не изменилось».** У каждого файла есть отпечаток (ETag), и при
  повторном визите сервер отвечает 304 без тела. Сколько браузер хранит
  файлы:
  - файлы сборки и шрифты — год;
  - картинки — неделю, потом проверяет их в фоне;
  - страницы — проверяет при каждом визите.
- **Тексты сайта не скачиваются зря.** Раньше при каждом открытии сайт
  скачивал с сервера весь контент на 6 языках — 556 КБ без сжатия. На
  медленном интернете эта загрузка обрывалась через 3,5 с, и такие
  посетители не видели правок из админки.

  Теперь сборка вшивает в сайт отпечаток контента. Если в админке ничего не
  меняли, сервер отвечает «всё актуально» (0 байт). Если меняли — отдаёт
  контент сжатым (~130 КБ).
- **Заставка первого кадра.** Пока грузятся скрипты, вместо белого экрана
  видна тёмная заставка с логотипом и размытым кадром первого баннера.
- **Офлайн-кеш** (`public/sw.js`). Уже после первого визита сайт
  открывается без связи. Как он работает:
  - файлы сборки и шрифты берутся из кеша;
  - картинки показываются из кеша и обновляются в фоне;
  - страница берётся сначала из сети;
  - API, админка, кабинеты и файлы чата не кешируются никогда.
- **Защита после обновления.** Если в браузере осталась старая страница и
  она просит уже удалённый файл, сайт один раз перезагружается на свежую
  версию.
- **Netlify.** Добавлены правила кеширования для `/fonts`, `/img` и
  `sw.js`. Сжатие там делает сам Netlify.

**Для разработчика:**

- **`server/compress.js`** — выбор и сжатие ответа, отпечаток контента.
  Модуль общий для сервера и сборки.
- **`server/static.js`** — ETag и ответ 304, сжатие, правила кеша.
- **`/api/content`.** Параметр `?have=<отпечаток>` даёт ответ 204. Кроме
  того, у ответа есть ETag и сжатие.
- **`vite.site.config.js`** — считает отпечаток контента
  (`__OLAN_CONTENT_HASH__`) и вставляет в заставку превью первого баннера.
- **`sw.js`.** Если меняете в нём правила кеширования, поменяйте `VERSION`:
  старые кеши удалятся сами.

## v45

**Новый дизайн в стиле hikvision.com.** Белая корпоративная основа, фирменный
синий из логотипа вместо красного Hikvision, шрифт Onest с родной кириллицей.

- **Шапка.** Над баннером прозрачная, при прокрутке белая. При движении вниз
  прячется, при движении вверх возвращается. «Продукты» и «Решения»
  раскрываются мега-меню во всю ширину с фотографиями приборов. На телефоне
  меню выезжает шторкой.
- **Баннеры на главной** — новый раздел админки «Баннеры на главной». Пять
  кадров во весь экран: медленный наезд камеры, параллакс от мыши и
  прокрутки, зерно плёнки, заголовок проявляется по словам. Эффекты привязаны
  к предметам на фото:
  - перекрёсток — вспышка ИК-подсветки и рамка захвата на машине;
  - трасса — волны радара и метки скорости;
  - мобильный комплекс — солнечные блики и мигающий индикатор;
  - полоса для автобусов — блик на стекле камеры;
  - Wider — живой панорамный экран.

  Внизу вкладки с прогрессом, кнопка паузы, работают свайп и стрелки
  клавиатуры. Автопрокрутка останавливается при наведении и когда баннер
  не виден.
- **Лента всех продуктов.** Раздел прилипает к экрану, и прокрутка страницы
  вниз двигает ленту вправо: 6 комплексов фиксации и 10 продуктов группы.
  Есть счётчик, полоса прогресса и вкладки для перехода к группе. Если в
  системе включено «уменьшение движения», лента становится обычной
  горизонтальной.
- **Разделы главной:**
  - решения — панели раскрываются при наведении;
  - направления — вкладки с большим кадром;
  - «OLAN в цифрах» — счётчики на тёмном фото;
  - проекты, «Почему OLAN», контакты;
  - тёмный подвал с колонками продуктов.
- **Wider — новый продукт** (Продукты группы → wider): панорамный мягкий
  мультитач-экран 123″. На его странице: цифры, возможности, живые
  иллюстрации (касания, звук, батарея, брендирование), характеристики,
  клиенты и кнопка «Перейти на сайт Wider» на touchwider.com. Пока фото
  нет, вместо него рисуется анимированный экран. Загруженное в админке фото
  заменит анимацию.
- **Страница продукта** переделана для всех продуктов группы: крупный первый
  экран, липкое меню разделов. Блоки собираются только из заполненных полей.
- **Внутренние страницы** получили заголовок с хлебными крошками. Бирюзовые
  цвета старых страниц переведены на фирменный синий без переписывания
  самих страниц.
- Все подписи новых блоков переведены на 6 языков.

**Загрузка стала легче:**

- **Фото.** Для каждого фото приборов сделан WebP трёх ширин и отдельный
  вертикальный кадр для телефона: вместо 40,9 МБ теперь 4,6 МБ. Браузер
  берёт размер по экрану, а пока фото грузится, видно размытое превью.
- **Иконки.** Вместо всех 1500 иконок (800 КБ) в стартовый файл попадают
  около 90 нужных. Редкая иконка, выбранная в админке, догружается отдельно.
- **Отложенная загрузка.** При открытии страницы не грузятся библиотека
  анимаций и окно карточки прибора. Разделы ниже первого экрана подгружаются
  при прокрутке, чат — после первого действия посетителя.

**Для разработчика:**

- **Новые файлы.**
  - Стили: `styles/olan-base.css`, `olan-hero.css`, `olan-sections.css`.
  - Компоненты: `HeroSlider`, `WiderScreen`, `ProductRail`, `HomeSections`,
    `ProductModal`, `LazyMount`.
  - Помощники: `lib/icons.jsx`, `lib/img.jsx`, `lib/fx.jsx`.
  - Манифест картинок: `data/images.json`.
- **`scripts/audit-apps.mjs`.** Проверка «правки доходят до страницы» теперь
  метит баннер — это последний ключ контента, `HERO_SLIDES`. Разделы ниже
  первого экрана она включает событием `olan:mount-all`. Блок «Мониторинг»
  на главной больше не выводится, но его компонент остался.
- **Картинки из админки** показываются как есть: WebP для них пока не
  создаётся.

## v43

- **У каждого поля загрузки картинки подписан нужный размер.** Сайт
  вписывает фото в рамку и обрезает всё, что не поместилось, поэтому
  картинка другой пропорции теряет края. Теперь под кнопкой «Загрузить
  с компьютера» написано: «Нужный размер: 1600 × 1200 px (пропорции 4:3)»
  и где именно на сайте эта картинка показывается.

- Размеры взяты из вёрстки, а не на глаз. Везде, где сайт показывает
  загруженные фото, рамка 4:3: направления, продукты группы, проекты,
  профиль компании. У приборов рамка плавает от 5:4 до 3:2 в зависимости
  от ширины экрана — для них 4:3 лучший компромисс, и подсказка советует
  держать прибор в центре с запасом по краям.

- **Превью показывает обрезку так же, как сайт.** Раньше оно было
  квадратным и не давало понять, что срежется. Теперь это рамка 4:3
  с той же обрезкой, что увидит посетитель.

- **Автоматическая проверка каждой картинки.** Админка читает настоящий
  размер файла и сравнивает с рамкой:
  «⚠ пропорции 16:9, а рамка 4:3 — обрежется около 25% слева и справа»
  или «✓ Пропорции подходят — картинка покажется полностью». Предупреждает
  и о слишком маленьких картинках, которые будут нечёткими на большом
  экране. Для списков (фото приборов) разбор у каждой картинки свой.

- Рамки описаны в одном месте — `apps/admin/src/app/lib/imageFrames.js`.
  Если на сайте поменяется вёрстка, достаточно поправить там.

- `npm run audit:admin` проверяет, что подсказка о размере стоит во всех
  пяти разделах с картинками.

## v42

- **Исправлено: загруженные картинки показывались битой иконкой.** Сама
  загрузка работала, ломалось превью, поэтому казалось, что файл не ушёл.
  Причин было две:
  - превью брало картинку с адреса самой админки. При разработке админка
    открыта на порту 9000, а картинки раздаёт сервер на 3001 — файла
    по такому адресу нет. Теперь адрес собирается от сервера;
  - если превью хоть раз не загрузилось, компонент запоминал «сломано»
    навсегда, и следующие картинки тоже выглядели битыми. Теперь новый
    путь — новая попытка.

- **Исправлено: в семи разделах админки текстовые поля превратились
  в вложенные объекты.** В универсальном редакторе список языков не
  содержал арабского, а у каждого текстового поля есть ключ `ar`. Редактор
  переставал узнавать такие поля и рисовал «▶ Заголовок», «▶ Примечание»
  с шестью сырыми строками внутри. Задевало «Профиль компании»,
  «Направления», «Задачи заказчика», «Продукты группы», «Модели работы»,
  «Этапы и SLA» и «Команду».

- **«Продукты группы» — список, как в «Решениях».** Каждый продукт —
  отдельная строка с номером и названием: `02 · W-SPACE и URALAN`.
  Клик открывает подробности. Так же теперь выглядят все разделы на
  универсальном редакторе. Вложенные записи тоже подписаны осмысленно,
  а не «Запись 4».

- Удаление целой записи верхнего уровня спрашивает подтверждение.

- **Исправлено: кабинет менеджера при разработке не работал.** Он открыт
  на порту 9091, а этого порта не было в списке портов разработки —
  кабинет отправлял запросы сам себе. Порт добавлен во все приложения.

- Вложения в переписке кабинетов тоже берутся с сервера, а не с адреса
  страницы — та же ошибка, что с превью.

- **Новая проверка `npm run audit:admin`**: входит в админ-панель,
  открывает все 17 разделов, раскрывает первую запись в каждом и следит,
  чтобы не было ошибок и сырых языковых полей. Отдельно проверяет, что
  превью картинок в режиме разработки берётся с сервера. Проверено: со
  старым списком языков тест находит 198 сырых полей в «Профиле компании».

## v41

- **Проверено обратное направление: правка в коде доходит до админ-панели.**
  Изменение, добавление и удаление прямо в `siteData.js` подхватываются
  сервером и появляются в админке в течение двух с половиной секунд —
  ровно столько она ждёт между опросами версии.

- Если в админке есть несохранённые правки, она не перетирает их молча,
  а показывает предупреждение, что файл изменили в коде.

- **Исправлено: опечатка в `siteData.js` роняла весь сайт.** Файл правят
  руками, и в момент правки он почти всегда сломан — недописанная кавычка,
  лишняя запятая. Сервер отвечал ошибкой 500, и посетитель видел пустую
  страницу. Теперь при неудачном чтении отдаётся последняя рабочая версия,
  а причина пишется в лог. Правка применится, как только файл снова станет
  целым — перезапуск не нужен.

## v39

- **Номера в ленте мониторинга генерируются по правилам шести стран СНГ.**
  Ручной ввод убран. Каждый номер собирается по формату своей страны
  и с существующим кодом региона:

  | Страна | Пример |
  |---|---|
  | Узбекистан | `01 R 456 CC UZ` |
  | Россия | `В 518 РХ 78 RUS` |
  | Казахстан | `486 FTG 04 KZ` |
  | Кыргызстан | `03 KG 090 CDF` |
  | Таджикистан | `8652 BH 01 TJ` |
  | Беларусь | `6352 BK-5 BY` |

- Коды регионов выверены по открытым источникам: у Беларуси их ровно
  семь (1–7), у Кыргызстана девять (01 Бишкек, 02 Ош, 03–09 области),
  у Таджикистана семь действующих, у Казахстана двадцать с учётом новых
  областей, у Узбекистана четырнадцать, у России — список действующих
  без исторических.

- Буквы в каждой стране свои: Россия, Беларусь и Таджикистан используют
  только кириллические буквы, совпадающие по начертанию с латиницей;
  Казахстан, Кыргызстан и Узбекистан — латиницу.

- Страны идут вперемешку. Узбекистану дан больший вес: сайт узбекской
  компании, и лента должна выглядеть местной.

- Проверено на 20 000 сгенерированных номерах: ни одного с неверным
  форматом или несуществующим регионом.

- Правила вынесены в `apps/site/src/app/lib/plates.js` — там же меняется
  список стран и частота каждой.

Исправление четырёх накопившихся ошибок.

**Правки контента не доходили до сайта.** `contentStore` подставлял только
старые разделы и ничего не знал о тех, что появились с v11: продукты,
профиль компании, направления, команда, задачи, модели сотрудничества.
Теперь охвачены все блоки.

**Системная тема не срабатывала.** Версии до v18 записывали тему в хранилище
при каждом заходе, даже когда посетитель её не выбирал. У всех, кто открывал
сайт раньше, там осталось «решение», перекрывавшее определение по системе.
Ключ заменён на новый, старая запись игнорируется.

**Шапка и заголовки.** Название компании шло двумя строками — шапка была
вдвое выше нужного. Заголовок первого экрана был `text-5xl md:text-7xl`,
то есть 4,5rem поверх уже увеличенного корня. Оба переведены на плавающие
размеры с потолком. Базовый размер шрифта считался с обращением к самому
себе и переведён на пиксели.

**Радар** переписан на SVG: угол сектора задаётся числом, а не подбирается
градиентами. Шлейф идёт позади луча, отметки вспыхивают при его проходе.

## v18

Тема подстраивается под систему посетителя.

- При первом заходе сайт открывается в той теме, что стоит в операционной
  системе: тёмная у системы — тёмный сайт, светлая — светлый.

  она превратилась бы в «решение посетителя» и заморозилась навсегда.
- В index.html добавлен короткий скрипт: тема ставится до отрисовки,
  чтобы у посетителя с тёмной системой не мелькал белый экран.

- Кнопка «Отменить» откатывает ровно один шаг и перед этим показывает,
  что именно отменяется: добавление, удаление или правку конкретного поля
  с названием записи. Подряд идущие правки одного поля считаются одним шагом.
- Полный сброс контента остался отдельной кнопкой со стрелкой по кругу.

**Запуск**

- Сервер и фронтенды разведены по разным командам:
  `npm start` — сервер, `npm run dev` — сайт, админка и кабинет.
- `npm run dev` проверяет, поднят ли сервер, и предупреждает, если нет.

## v4

Роли, статусы заявок, мобильная админка и ускорение сайта.

**Интерфейс админ-панели**

- Кнопка «Сотрудники» перенесена в верхнюю строку, к кнопке выхода.
- Админка стала адаптивной. На узком экране разделы контента (Приборы, Решения
  и прочие) сворачиваются в одну кнопку с выпадающим меню, а «Сотрудники»
  и выход остаются на виду.
- У каждого оператора появились кнопки «Чаты» и «Заявки» — админ читает
  переписку и смотрит заявки, ничего не редактируя.

**Заявки**

- Три статуса: Новая, В разработке, Обработано.
- Видны дата и время поступления заявки.
- Сводка по статусам с числами; нажатие на статус раскрывает список заявок
  с данными клиента и текстом обращения.
- Статус меняет только оператор, за которым закреплена заявка.

**Кабинет**

- У менеджера слева список операторов, затем чаты выбранного, затем переписка.
- На вкладке «Заявки» слева операторы, справа сводка. Есть общий режим
  «Все операторы» и режим по конкретному оператору.
- Менеджер и администратор переписку только читают — запрет стоит на сервере.
- Оператор по-прежнему отвечает клиентам и меняет статусы своих заявок.

**Онлайн-чат**

- Имя оператора показывается клиенту буквами текущего языка сайта.
  Это транслитерация, а не перевод, и она не зависит от интернета.

**Скорость**

- Сайт разбит на части: сразу грузится только первый экран, остальное
  подгружается по мере прокрутки. Начальный файл уменьшился с 497 до 169 КБ.
- Библиотеки вынесены в отдельные файлы и кешируются браузером.
- Тяжёлые пакеты готовятся заранее, поэтому dev-сервер стартует быстрее.

## v3

Сотрудники, распределение обращений и исправление запуска.

**Менеджеры и операторы**

- Новая вкладка **Сотрудники** в админ-панели.
- Менеджеры показаны карточками, внутри каждой — привязанные к ней операторы.
- При создании оператора менеджер выбирается в списке; оператора можно перевести
  к другому менеджеру.
- Пароли задаёт и меняет только администратор. Смена пароля сразу разлогинивает
  сотрудника.
- Удаление спрашивает подтверждение и называет имя именно того сотрудника,
  на которого нажали.
- Удалили менеджера — его операторы случайно расходятся к оставшимся.
  Удалили оператора — его клиенты, чаты и заявки переходят к другим операторам.
- Учётки сотрудников больше не хранятся в `.env`.

**Распределение обращений**

- Сообщения из чата и заявки с формы раздаются операторам случайно, но «липко»:
  один клиент всегда попадает к одному и тому же оператору.
- Клиент узнаётся по email или телефону — хватает совпадения любого из двух.
- Оператор видит только свои обращения, менеджер — обращения всех своих операторов.
- Ответить в чужой чат сервер не даёт.
- В кабинете появилась вкладка «Заявки» рядом с «Чатами».
- Вход в кабинет теперь по токену сессии, пароль на устройстве не сохраняется.

**Исправления**

- Сайт больше не показывает белый экран, если API-сервер не запущен: страница
  рисуется сразу, контент с сервера подтягивается потом.
- Vite выводит одну рабочую ссылку вместо списка сетевых адресов.
  Доступ по сети включается переменной `VITE_HOST` в `.env`.

## v1

Сборка трёх отдельных проектов в один.

- Сайт, админ-панель и кабинет оператора объединены в одну папку.
- Сервер вынесен из операторской части наверх и обслуживает все три приложения:
  чат на сайте, переписку у оператора и контент в админке.

  отдельной базе. Связь работает в обе стороны: правки в админке переписывают файл,
  правки в файле подтягиваются в админку.
- Перед каждой записью создаётся резервная копия в `server/data/backups/`.
- Сервер умеет раздавать собранные приложения сам, без Vite: `/`, `/admin/`, `/operator/`.
- Добавлены задачи VSCode для запуска в отдельных терминалах.
