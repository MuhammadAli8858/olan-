# История версий

Каждая сборка получает свой номер. Файл архива называется `Olan vN.zip`,
внутри папка всегда `olan` — чтобы путь на компьютере не менялся.

---

## v18 — текущая

Тема подстраивается под систему посетителя.

- При первом заходе сайт открывается в той теме, что стоит в операционной
  системе: тёмная у системы — тёмный сайт, светлая — светлый.
- Если посетитель переключил тему кнопкой, дальше уважается только его
  выбор: системная настройка больше не вмешивается, решение сохраняется
  между визитами.
- Пока выбор не сделан вручную, сайт следит за системой вживую —
  переключили тёмный режим в системе, сайт меняется без перезагрузки.
- Автоматически определённая тема не записывается в хранилище, иначе
  она превратилась бы в «решение посетителя» и заморозилась навсегда.
- В index.html добавлен короткий скрипт: тема ставится до отрисовки,
  чтобы у посетителя с тёмной системой не мелькал белый экран.

## v17

Радар в блоке мониторинга.

- Шлейф луча шёл впереди линии, а не позади — из-за неверной точки
  отсчёта в conic-gradient. Сектор выглядел неподвижным клином.
  Теперь свечение занимает ровно тот сектор, который луч уже прошёл.
- Свечение слабеет к краю круга, как на настоящем экране.
- Момент вспышки каждой отметки вычисляется из её координат, а не
  подбирается вручную: сдвинули точку — время пересчитается само.
- Эхо гаснет примерно за пол-оборота, а не тянется весь круг.

- Сайт разбит на части: сразу грузится только первый экран, остальное
  подгружается по мере прокрутки. Начальный файл уменьшился с 497 до 169 КБ.
- Библиотеки вынесены в отдельные файлы и кешируются браузером.
- Тяжёлые пакеты готовятся заранее, поэтому dev-сервер стартует быстрее.

## v3

Сотрудники, распределение обращений и исправление запуска.

**Менеджеры и операторы**

- Новая вкладка **Сотрудники** в админ-панели.
- Менеджеры показаны карточками, внутри каждой — привязанные к ней операторы.
- При создании оператора менеджер выбирается в списке; оператора можно перевести
  к другому менеджеру.
- Пароли задаёт и меняет только администратор. Смена пароля сразу разлогинивает
  сотрудника.
- Удаление спрашивает подтверждение и называет имя именно того сотрудника,
  на которого нажали.
- Удалили менеджера — его операторы случайно расходятся к оставшимся.
  Удалили оператора — его клиенты, чаты и заявки переходят к другим операторам.
- Учётки сотрудников больше не хранятся в `.env`.

**Распределение обращений**

- Сообщения из чата и заявки с формы раздаются операторам случайно, но «липко»:
  один клиент всегда попадает к одному и тому же оператору.
- Клиент узнаётся по email или телефону — хватает совпадения любого из двух.
- Оператор видит только свои обращения, менеджер — обращения всех своих операторов.
- Ответить в чужой чат сервер не даёт.
- В кабинете появилась вкладка «Заявки» рядом с «Чатами».
- Вход в кабинет теперь по токену сессии, пароль на устройстве не сохраняется.

**Исправления**

- Сайт больше не показывает белый экран, если API-сервер не запущен: страница
  рисуется сразу, контент с сервера подтягивается потом.
- Vite выводит одну рабочую ссылку вместо списка сетевых адресов.
  Доступ по сети включается переменной `VITE_HOST` в `.env`.

## v2

Устойчивость установки на Windows.

- Убраны npm workspaces. Теперь одна `package.json` и один `node_modules` в корне,
  внутри `apps/` нет отдельных пакетов. Раньше пропажа одного вложенного
  `package.json` ломала установку целиком.
- Настройки сборки переехали в корень: `vite.site.config.js`, `vite.admin.config.js`,
  `vite.operator.config.js`.
- Версии пакетов зафиксированы точно, приложен `package-lock.json`.
- Добавлен `npm run check` — проверяет версию Node, целостность файлов, полноту
  установленных пакетов и объясняет проблему по-русски вместо простыни из esbuild.
  Запускается автоматически перед каждым стартом.
- Добавлены `npm run clean` и `npm run reinstall` вместо ручных команд удаления.
  Список удаляемого зашит в код, тронуть исходники они не могут.
- Добавлен `.npmrc` с повторными попытками загрузки.

## v1

Сборка трёх отдельных проектов в один.

- Сайт, админ-панель и кабинет оператора объединены в одну папку.
- Сервер вынесен из операторской части наверх и обслуживает все три приложения:
  чат на сайте, переписку у оператора и контент в админке.
- Контент сайта хранится прямо в `apps/site/src/app/data/siteData.js`, а не в
  отдельной базе. Связь работает в обе стороны: правки в админке переписывают файл,
  правки в файле подтягиваются в админку.
- Перед каждой записью создаётся резервная копия в `server/data/backups/`.
- Сервер умеет раздавать собранные приложения сам, без Vite: `/`, `/admin/`, `/operator/`.
- Добавлены задачи VSCode для запуска в отдельных терминалах.
